## Failures

### 1. `tests/pglite/toast-stress.test.ts` — TOAST: ALTER TABLE ADD COLUMN with large default > cache=tiny (4 pages)

- **Duration**: 34,732ms (timeout at 30,000ms)
- **Error**: `Test timed out in 30000ms`
- **Root cause**: Structural timeout flake, not a code regression.

**Analysis**: The test adds a TEXT column with a 4KB TOAST'd default to a 10-row table. With only 4 pages (32KB) of cache, every page access during ALTER TABLE's rewrite and TOAST chunk storage evicts a dirty page. The timing pattern across cache sizes confirms this is a cache-pressure scaling issue:

| Cache size | Pages | Duration |
|-----------|-------|----------|
| tiny      | 4     | 34,732ms (FAILED) |
| small     | 16    | 7,861ms  |
| medium    | 64    | 4,590ms  |
| large     | 4096  | 4,548ms  |

The tiny-cache variant is consistently close to the 30s limit. In this run's environment (container with shared resources), it exceeded the threshold. Other tests in the same file handle this by omitting `@fast` for tiny-cache variants (see `cache-pressure-persistence.test.ts` lines 61-66), but `toast-stress.test.ts` runs all sizes uniformly.

**Fix options** (ordered by preference):

1. **Increase the per-test timeout for the cache=tiny variant of this specific scenario.** Add a timeout parameter: `it(\`cache=tiny ...\`, async () => { ... }, 60000)`. This is the most targeted fix — the test itself is correct, it just needs more time under extreme cache pressure.

2. **Reduce workload**: Lower the row count from 10 to 5 or reduce the TOAST default size from 4000 to 2000 bytes. This would speed up the tiny-cache variant but weakens the stress test.

3. **Skip tiny for this scenario**: Follow the `cache-pressure-persistence.test.ts` pattern and exclude tiny from this specific scenario. Loses coverage for a real edge case.
